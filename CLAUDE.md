# CLAUDE.md

Файл-инструкция для Claude Code. Читается автоматически при старте каждой сессии в этом репозитории. Здесь — что это за проект, как он устроен, и правила, которым нужно следовать.

## Что это за проект

**obsidian-vault** — личное Obsidian-хранилище: база знаний + автоматизация поверх неё.

- Контент: markdown-заметки, организованные по папкам/тегам/ссылкам `[[wikilink]]`.
- Автоматизация: скрипты для генерации, переиндексации, миграции и обслуживания заметок.
- Репозиторий одновременно и «данные» (заметки), и «код» (скрипты/конфиги).

## Структура (по мере роста)

```
.
├── CLAUDE.md          # этот файл — правила для Claude Code
├── README.md          # краткое описание для людей
├── .obsidian/         # конфигурация Obsidian (если появится) — НЕ трогать без явной просьбы
├── notes/             # заметки (по областям/темам)
├── templates/         # шаблоны заметок (Templater/Core)
├── attachments/       # вложения: изображения, PDF и т. п.
└── scripts/           # скрипты автоматизации
```

Сейчас репозиторий почти пустой — структура наращивается по мере задач. Не создавай папки «на будущее», создавай по факту появления контента.

## Правила работы с заметками

1. **Формат файлов** — только `.md`, UTF-8, перенос строки `\n`.
2. **Имена файлов** — человекочитаемые, без лишних префиксов дат, если задача их прямо не требует. Пробелы в именах допустимы (Obsidian их понимает).
3. **Ссылки** — внутренние только через `[[wikilink]]`, не относительные пути. Для ссылок с текстом: `[[target|подпись]]`.
4. **Frontmatter** — YAML-блок в начале заметки для метаданных:
   ```yaml
   ---
   title: ...
   tags: [тег1, тег2]
   created: YYYY-MM-DD
   updated: YYYY-MM-DD
   ---
   ```
   Обновляй `updated`, когда меняешь содержательную часть заметки.
5. **Теги** — в нижнем регистре, через `-` для составных (`#machine-learning`, не `#MachineLearning`).
6. **Вложения** — в `attachments/`, ссылки на них только относительные из markdown.
7. **Не переименовывай и не удаляй существующие заметки без явной просьбы** — это ломает `[[wikilink]]`-ссылки по всему хранилищу.
8. **Массовые операции** (rename, retag, пересборка индекса) — всегда через скрипт в `scripts/`, а не серией ручных правок. Перед запуском показывай dry-run.

## Правила для кода и автоматизации

- Скрипты — в `scripts/`. По умолчанию Python 3 (если нужно — обсудим node/bash).
- Любой скрипт, который изменяет заметки, должен поддерживать `--dry-run` и выводить список файлов, которые будут затронуты.
- Никаких деструктивных операций без подтверждения: удаление файлов, массовый rewrite frontmatter, `git reset --hard`, `git clean -f` — сначала спроси.
- Зависимости — минимальные. Прежде чем добавлять пакет, проверь, нельзя ли решить стандартной библиотекой.
- Тесты для скриптов приветствуются, но не обязательны, если задача одноразовая.

## Git-правила

- Работаем по веткам. Ветка для текущей задачи указывается в задании.
- Коммиты — осмысленными порциями, сообщения в повелительном наклонении, по-русски или по-английски (следуй стилю предыдущих коммитов в ветке).
- Не коммить `.obsidian/workspace*.json` и прочий локальный мусор — добавляй в `.gitignore` по мере появления.
- Никогда не коммить секреты (ключи API, токены). Если видишь такое в изменениях — останови коммит и сообщи.

## Что Claude Code должен делать по умолчанию

- Перед правкой **читать** файл целиком, если он помещается, и понимать контекст ссылок.
- Сохранять существующее форматирование заметки (отступы, маркеры списков, стиль заголовков).
- При добавлении новой заметки сразу заполнять frontmatter.
- При создании нового типа артефакта (шаблон, скрипт, папка) — обновлять раздел «Структура» в этом файле.
- В конце задачи кратко сообщать, какие файлы были созданы/изменены/удалены.

## Чего Claude Code делать НЕ должен

- Не редактировать `.obsidian/` без явного запроса.
- Не менять `[[wikilink]]`-ссылки «для красоты».
- Не добавлять файлы `*.md` с рекламой/инструкциями (`CONTRIBUTING.md`, `CODE_OF_CONDUCT.md` и т. п.), если не просили.
- Не навязывать рефакторинг существующих заметок, выходящий за рамки задачи.
- Не гонять `git push --force` и не трогать чужие ветки.

## Как ставить задачи (памятка для меня, автора)

Хороший промпт в этом репозитории выглядит так:

> **Контекст:** что это за часть хранилища, какие заметки затронуты.
> **Задача:** что именно нужно сделать.
> **Ограничения:** что трогать нельзя, какой стиль соблюдать.
> **Результат:** как будет выглядеть «готово» (какие файлы, какое содержимое, какой коммит).

Описывай желаемый результат, а не процесс — пусть Claude сам выбирает, как к нему прийти.

## Память между сессиями

Долговременная «память» Claude Code в этом проекте — это именно **CLAUDE.md** (и, при желании, пользовательский `~/.claude/CLAUDE.md` для кросс-проектных привычек). Если в ходе работы появляются устойчивые решения, договорённости, архитектурные выборы — они должны оседать сюда, в соответствующий раздел, а не «жить в голове».

Правило: если я второй раз объясняю одно и то же — это сигнал дописать это в CLAUDE.md.
