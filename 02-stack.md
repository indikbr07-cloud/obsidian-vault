# Технологический стек

## Выбор

| Слой | Технология | Почему |
|---|---|---|
| **Backend** | Python 3.12 + FastAPI | Быстрый в разработке, хорошая типизация (Pydantic), автогенерация OpenAPI, легко читается. |
| **ORM / Миграции** | SQLAlchemy 2.0 + Alembic | Стандарт для Python, зрелый, нормально работает со сложными складскими запросами. |
| **База данных** | PostgreSQL 16 | Транзакции, JSONB, оконные функции (нужны для отчётов), надёжность. |
| **Frontend (веб)** | React 18 + TypeScript + Vite | Кассовый UI, админка, производственный экран — всё на одном стеке. |
| **UI-библиотека** | Mantine или shadcn/ui | Готовые компоненты для таблиц, форм, модалок — не тратим время на базовый UI. |
| **Мобильное (PWA)** | React + Vite PWA plugin + IndexedDB (Dexie) | Приложение закупщика: ставится на телефон, работает офлайн, синхронизируется при сети. |
| **Аутентификация** | JWT + refresh tokens | Стандарт, не усложняем до OAuth для MVP. |
| **Очереди / фоновые задачи** | Celery + Redis (или RQ) | OCR накладных, синхронизация закупщика, отчёты — асинхронно. |
| **OCR** | Yandex Vision OCR API (первичный) + Tesseract (fallback) | Yandex лучше распознаёт кириллические накладные и табличные данные. |
| **Файловое хранилище** | S3-совместимое (MinIO локально / Yandex Object Storage в проде) | Фото чеков, сканы накладных, отчёты. |
| **Упаковка** | Docker + docker-compose | Один `docker-compose up` поднимает всю систему на сервере пилотной столовой. |
| **CI/CD** | GitHub Actions | Автотесты и сборка образов при push. |
| **Тесты** | pytest (backend), Vitest + Playwright (frontend) | Стандарт. |

## Архитектура развёртывания

```
[Сервер в столовой или VPS]
   ├── nginx (reverse proxy, TLS)
   ├── backend (FastAPI) × 2 реплики
   ├── worker (Celery) × 1
   ├── postgres
   ├── redis
   └── minio (S3)

[Клиенты в точке]
   ├── POS на раздаче — веб в браузере на планшете/мониторе
   ├── Производственный экран на кухне — веб на планшете
   ├── Админка менеджера — веб на ПК
   └── Приложение закупщика — PWA на смартфоне
```

## Принципы, которые фиксируем на уровне стека

1. **Монорепо** — весь код в одном репозитории. Проще для агентов.
2. **Модульность backend** — каждый модуль системы живёт в своей папке `app/modules/*` с чётким API. Модульный агент правит только свою папку.
3. **Общие контракты через OpenAPI** — frontend тянет типы из автогенерируемой схемы. Меньше ошибок на швах.
4. **Миграции через Alembic, одна ветка** — никаких ручных SQL в прод.
5. **Фича-флаги в БД** — включение/выключение модулей без перекомпиляции (нужно для поэтапного запуска в пилоте).
