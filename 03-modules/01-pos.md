# Модуль 1. POS на линии раздачи

## Назначение
Касса в конце линии раздачи: принять заказ, рассчитать стоимость, принять оплату, напечатать чек, списать проданные позиции с остатков линии раздачи.

## Пользователи
- Кассир (основной)
- Менеджер (для отмен, возвратов, закрытия смены)

## Основные сценарии
_(заполняет PO)_

1. Гость подошёл с подносом — кассир видит блюда, пробивает их на кассе.
2. ...

## Экраны
- Главный экран кассира: сетка блюд, текущий чек, итог.
- Экран оплаты: выбор способа (нал / карта), ввод суммы, сдача.
- Экран смены: открытие, закрытие, Z-отчёт.

## Бизнес-правила
- Блюдо нельзя пробить, если его остаток на линии раздачи = 0 (или можно? уточнить у PO).
- Отмена позиции — требует права менеджера / PIN?
- Округление итога?
- Весовые блюда — цена × вес, ввод веса с весов или вручную?

## API (чёрные ящики, которые дёргает POS)
- `POST /api/pos/sale` — зафиксировать продажу, получить номер чека.
- `GET /api/line/stock` — текущие остатки на линии раздачи.
- `POST /api/shifts/open`, `POST /api/shifts/close`.

## Интеграции
- Весы (опционально) — уточнить у PO.
- Фискальный регистратор — не в MVP, пока чек в PDF.
- Эквайринг — не в MVP, оплата картой в ручном режиме через отдельный терминал банка.

## Нефункциональные
- Офлайн-режим: при падении сети касса должна продолжать работать, чеки синхронизируются при восстановлении.
- Скорость: выбор блюда → добавление в чек < 200 мс.

## Открытые вопросы для PO
- [ ] Есть ли весовые блюда на раздаче? Если да — какие весы уже стоят?
- [ ] Нужны ли скидки (процентные, абсолютные, по категориям клиентов — студент/сотрудник)?
- [ ] Нужны ли комплексные обеды (набор по фиксированной цене)?
- [ ] Есть ли безналичный расчёт через эквайринг сейчас, или только нал?
- [ ] Кто именно работает на кассе — один человек всю смену, или несколько кассиров?
- [ ] Распечатка чека обязательна, или можно без печати (на экране QR/номер)?
