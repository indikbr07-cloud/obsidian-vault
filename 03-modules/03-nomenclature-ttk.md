# Модуль 3. Номенклатура и ТТК

## Назначение
Справочник всего, что есть в системе: ингредиенты (сырьё), готовые блюда, полуфабрикаты, модификаторы. Технологические карты (ТТК) — рецепты: сколько граммов каждого ингредиента идёт на блюдо, какие потери при обработке, какая расчётная себестоимость.

## Пользователи
- Шеф-повар / технолог (составляет ТТК)
- Менеджер (смотрит себестоимость, правит цены)

## Как устроено сейчас (со слов PO)

**Меню** — сейчас используется R-Keeper. Итоговый объём меню:

| Категория | Количество позиций |
|---|---|
| Первые блюда | 2–4 |
| Вторые блюда | ~20 |
| Гарниры | ~10 |
| Салаты | ~12 |
| Напитки (горячая вода, чай, кофе, соки и т.д.) | ~20 |
| Выпечка | ~10 |
| **ИТОГО** | **~74 позиции** |

Оценка PO «40–50 блюд» относилась только к еде без напитков и выпечки — это сходится с суммой первых+вторых+гарниров+салатов ≈ 44–46. Общая картина с напитками и выпечкой даёт ~74 позиции.

**R-Keeper** — стоит скорее всего R-Keeper 4 или 5 (PO точно не помнит), **без API**. Это означает:
- Живая синхронизация между R-Keeper и нашей системой невозможна.
- Переход — одномоментный: экспорт из R-Keeper → импорт в нашу систему → переключение точки на новую систему.
- У PO есть подрядчик, который обслуживает R-Keeper и умеет делать выгрузки.
- **Действие PO до начала кодинга**: запросить у подрядчика экспорт справочников (ингредиенты, блюда, ТТК, закупочные цены) в любом формате — Excel, XML, CSV или бэкап базы.

**ТТК** — уже составлены и ведутся в R-Keeper. Конкретный формат станет ясен после получения экспорта.

**Изменяемость меню** — 80% стабильно, 2–5 блюд в день могут отсутствовать. **Формального стоп-листа в R-Keeper нет**: кассир просто «знает», что сегодня борщ закончился, и не пробивает его. Это текущая слабость, которую **новая система закроет как отдельную фичу** (см. «Решения» ниже).

**Себестоимость** — рассчитывается R-Keeper через калькуляцию от закупочных цен; ежедневно не пересчитывается. PO предполагает, что метод — средневзвешенная или по последней закупочной, но точно не знает.

## Решения (зафиксированы)

1. **Метод расчёта себестоимости — средневзвешенная** по остаткам на складе сырья. Причины: стабильнее, чем «по последней цене» (не скачет при разовой дорогой закупке), точнее для foodcost-отчёта, проще для объяснения шефу. Последняя закупочная цена всё равно хранится в карточке ингредиента для справки.
2. **Стоп-лист — обязательная фича новой системы.** Кассир или менеджер ставит блюдо в стоп → оно пропадает с кассового экрана до снятия стопа. Автоматический стоп: если остаток на линии раздачи = 0 и на кухне = 0 — система предлагает поставить в стоп.
3. **Миграция из R-Keeper — одномоментная через экспорт**, без живого sync (R-Keeper без API). Пишем импортёр под формат, который пришлёт подрядчик.

## Действия для PO
- [ ] Запросить у подрядчика R-Keeper **экспорт справочников** (ингредиенты, блюда, ТТК, закупочные цены, история продаж — если возможно) в любом удобном формате. Уточнить версию R-Keeper.

## Основные сценарии

1. Шеф заводит новое блюдо «Котлета по-киевски».
2. Прописывает состав: 150 г куриного филе, 30 г масла, 20 г панировки, яйцо 1/2 шт.
3. Указывает процент потерь на обработке.
4. Система считает себестоимость порции на основе текущих закупочных цен ингредиентов.
5. Шеф ставит продажную цену, видит маржу.
6. **Ежедневно**: из общего меню ~80 позиций формируется «меню на сегодня» — убираются блюда в стоп, добавляются сезонные. Кассир и повар видят только актуальные блюда.

## Экраны
- Справочник ингредиентов: название, единица (кг, шт, л), текущая закупочная цена, поставщик по умолчанию, категория.
- Справочник блюд: название, категория, цена продажи, себестоимость, маржа, признак «в основном меню».
- Карточка ТТК: состав блюда, процент потерь, вес нетто/брутто, КБЖУ (опционально).
- Справочник модификаторов (соусы, размеры, добавки).
- **Меню на день**: управление активностью блюд (в стоп / в меню) — ключевой ежедневный экран.

## Бизнес-правила
- Себестоимость пересчитывается при изменении цены ингредиента (метод — после уточнения).
- ТТК версионируется: если поменяли рецепт — старые продажи остаются с расчётом по старой версии.
- Блюдо может быть «составным» — включать не ингредиенты, а другие блюда / полуфабрикаты.
- **Стоп-лист на сегодня**: блюдо в стопе не показывается на кассе и в производственном плане, но остаётся в справочнике.

## API
- CRUD `/api/nomenclature/ingredients`
- CRUD `/api/nomenclature/dishes`
- CRUD `/api/nomenclature/ttk`
- `GET /api/nomenclature/dishes/{id}/cost` — текущая расчётная себестоимость.
- `GET /api/nomenclature/menu?date=...` — меню на конкретный день.
- `POST /api/nomenclature/stop-list` — управление стопами.

## Миграция из R-Keeper
Если R-Keeper предоставляет экспорт (чаще всего — в Excel или XML), пишем импортёр:
- Ингредиенты (номенклатура сырья)
- Блюда (номенклатура готовой продукции)
- ТТК (состав блюд)
- История закупочных цен (если есть)

Альтернатива — ручной перенос. При 80 блюдах и 100–200 ингредиентах — это 1–2 дня работы шефа или оператора.

## Открытые вопросы для PO
- [x] Сколько блюд в меню? — **~74 позиции**, из них ~44–46 «еда» (первые+вторые+гарниры+салаты) и ~30 напитков+выпечки.
- [x] R-Keeper версия и выгрузка — **R-Keeper 4 или 5, без API. Есть подрядчик, делает выгрузку в любом формате.** PO запросит экспорт.
- [x] Метод расчёта себестоимости — **решено: средневзвешенная по остаткам сырья.**
- [x] Механика стоп-листа — **решено: стоп-лист будет новой фичей, ручной + автоматический при нулевом остатке.**
- [ ] **Сколько ингредиентов** примерно в обороте? (Для сырья — 100 / 200 / 500?) Можно оценить после экспорта из R-Keeper.
- [ ] **Полуфабрикаты**: есть ли заранее готовящиеся компоненты (бульон, соус, фарш), которые используются в нескольких блюдах?
- [ ] **Варианты размеров**: есть ли блюда с разными порциями (маленький/большой борщ, стандарт/XL гарнир) или модификаторы (с сыром / без / двойной)?
- [ ] **КБЖУ и аллергены**: нужны на экране гостя / в меню? Обязательны ли по санитарным нормам в вашей точке?
- [ ] **Комплексные обеды**: есть ли «обед по фиксированной цене = первое + второе + салат + напиток»?
- [ ] **Категоризация для кассы**: оставляем те же группы (первые / вторые / гарниры / салаты / напитки / выпечка), или нужно по-другому?
- [ ] **Сезонность цен**: цены на блюда фиксированные круглый год, или меняются (например, летнее меню дешевле)?
