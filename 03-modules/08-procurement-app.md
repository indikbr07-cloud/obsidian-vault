# Модуль 8. Мобильное приложение закупщика

## Назначение
Работа закупщика на оптовом рынке (Food City, Метро) за наличные. Закупщик получает наличные под отчёт, едет на рынок, быстро оформляет покупки в приложении, по возвращении всё автоматически становится приходом на складе, остаток наличных сверяется.

Ключевые условия работы:
- **Плохой интернет на рынке** — офлайн обязателен.
- **Быстрота ввода** — руки холодные, спешка, нужно за 15 секунд зафиксировать покупку.
- **Наглядный подотчёт** — закупщик и менеджер должны видеть: выдано / потрачено / осталось / куплено.

## Технологическая платформа
**PWA** — React + Vite PWA plugin. Ставится на телефон через «Добавить на главный экран». Работает офлайн на IndexedDB (Dexie), синхронизируется с сервером по сети.

## Пользователи
- Закупщик (основной)
- Менеджер (выдаёт деньги, принимает отчёт)

## Основные сценарии

### 1. Выдача наличных под отчёт
- Менеджер в веб-админке оформляет документ «Выдача закупщику»: сумма, цель, дата.
- Сумма появляется в балансе закупщика в приложении.

### 2. Закупка на рынке
- Закупщик открывает приложение — видит список заявок шефа (опционально) и текущий баланс наличных.
- Быстрый ввод покупки:
  - Выбор ингредиента из справочника (поиск по названию, частые в топе).
  - Количество / вес.
  - Цена за единицу или общая сумма.
  - Фото чека / ценника (опционально, для спора по цене).
- Данные сохраняются в IndexedDB, работают офлайн.
- В шапке всегда виден остаток: `выдано − потрачено = X ₽`.

### 3. Синхронизация
- По возвращении (или при появлении сети) — приложение пушит все покупки на сервер.
- На сервере они группируются в документ «Приход от закупщика», автоматически оприходуются на склад сырья.

### 4. Закрытие отчёта
- Закупщик возвращает сдачу в кассу — в приложении отмечает «возврат N ₽».
- Баланс по закупщику должен сойтись: `выдано = потрачено + возврат`.
- Если расхождение — менеджер видит алерт.

## Экраны приложения
- Главный: баланс наличных + кнопка «Добавить покупку».
- Добавить покупку: форма (ингредиент, количество, цена, фото).
- Список заявок от шефа (что нужно купить).
- История покупок за сессию.
- Возврат наличных в кассу.

## Бизнес-правила
- Ингредиент в покупке должен быть из справочника (или можно создать новый на лету с пометкой «новый, проверить»).
- Цена покупки фиксируется как закупочная для этой партии — влияет на себестоимость блюд.
- Геометка (опционально) — где куплено, привязка к рынку/точке.

## API
- `GET /api/procurement/balance?procurer_id=...`
- `GET /api/procurement/requests` — заявки шефа.
- `POST /api/procurement/purchases/bulk` — синхронизация офлайн-покупок.
- `POST /api/procurement/return` — возврат наличных.
