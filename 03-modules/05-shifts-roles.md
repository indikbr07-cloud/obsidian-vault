# Модуль 5. Смены и роли

## Назначение
Учёт сотрудников, их ролей и рабочих смен. Каждое действие в системе (продажа, производство, приёмка) привязано к смене и сотруднику. Это основа для отчётов выручки по кассирам, контроля работы и зарплатного учёта.

## Пользователи
- Менеджер (заводит сотрудников, назначает роли)
- Все сотрудники (открывают/закрывают свои смены)

## Роли (минимум)
- `cashier` — кассир, работает на POS.
- `cook` — повар, работает с производственным экраном.
- `storekeeper` — кладовщик, оформляет приход и инвентаризацию.
- `procurer` — закупщик, работает в PWA-приложении.
- `manager` — менеджер, доступ ко всем отчётам и корректировкам.
- `admin` — владелец, все права + настройки системы.

## Основные сценарии
1. Менеджер заводит сотрудника, выдаёт PIN или логин/пароль.
2. Сотрудник приходит на смену, открывает смену на своём рабочем месте (POS / кухня / склад).
3. В течение смены все его действия привязываются к `shift_id` и `user_id`.
4. По окончании смены — закрывает её. Для кассира формируется Z-отчёт (выручка, количество чеков, средний чек, нал/безнал).

## Бизнес-правила
- Одна касса = одна открытая смена одновременно.
- Смена не закрывается автоматически в полночь (уточнить у PO — для столовой с дневным режимом это может быть иначе).
- Инкассация: при закрытии смены кассир сдаёт наличные, менеджер принимает — документ «Изъятие из кассы».

## API
- CRUD `/api/users`
- CRUD `/api/roles`
- `POST /api/shifts/open`, `POST /api/shifts/close`
- `GET /api/shifts/{id}/z-report`
- Аутентификация — JWT, PIN для кассиров (быстрый вход).
