## Архитектура «мегамозга» — operational intelligence для управления замами

**Контекст:** Ибрагим хотел автоматизацию: утреннее напоминание «на чём остановились вчера» + срез по задачам замов с проверкой соответствия приоритетам. В ходе разговора переформулировали запрос — это не мониторинг, а operational intelligence (слой 3 поверх контроля активности и управления задачами).

**Что обсудили / решили:**
- Разложили систему на 7 компонентов: модель роли, модель целей, модель процессов, слой наблюдения, слой сигналов, слой интерпретации, слой решений и памяти.
- Зафиксировали, что у Ибрагима уже есть: Кодекс связей (141 сигнал), Процессное ядро, Соглашения о ролях, YouGile как слой наблюдения, Протоколы координации.
- Выделили 4 пробела: нет петли обратной связи на уровне решений; «почему» не автоматизировано; нет карты зависимостей между замами; прогноз преждевременен (короткие ряды данных).
- Обсудили риск смещения от «контроля» к «слежке» — сформулировали правильную рамку: система для приоритизации внимания директора, а не для надзора.

**Остановились на:** согласились на рамку «приоритизация внимания директора» и перешли к MVP первого сценария — утренняя сводка «на чём остановились».

**Далее:** собрать документ «Архитектура мегамозга IThub» с картой всех 7 слоёв и фронтом работ по каждому заму — но не сейчас, а после того как MVP утренней сводки заработает.

## Источник «твоей нити» — откуда система узнаёт, над чем ты работал

**Контекст:** Ибрагим выбрал вариант «система читает чаты с Claude». Обсудили технические ограничения этого выбора.

**Что обсудили / решили:**
- Ограничение 1: Anthropic не даёт публичного API для чтения чатов. Три обходных пути (ручной экспорт, прокси-логгер через Telegram-бот, ведение в Obsidian) — у каждого своя цена.
- Ограничение 2: сигнал vs шум. В сессиях с Claude половина — черновая работа, половина — стратегия. Без маркировки система не различит.
- Приняли гибридную модель: основной канал — Obsidian-заметка «Директорский журнал», дополнительный — экспорт логов Claude (если настроится).

**Остановились на:** решение — основной источник `Директорский журнал/` в vault, ведётся совместно (Ибрагим + Claude).

**Далее:** закрыто — перешли к реализации.

## Канал доставки утренней сводки — Claude Code vs YouGile vs гибрид

**Контекст:** Ибрагим спросил, не лучше ли присылать сводку в YouGile-карточку или личные сообщения до начала сессии в Claude Code.

**Что обсудили / решили:**
- Вариант 1 (Claude Code через `CLAUDE.md`) — работает сегодня, без инфраструктуры, но только при открытии сессии. Это контекст, не напоминание.
- Вариант 2 (YouGile) — приходит до работы, виден с телефона, но требует n8n-интеграции от Алана.
- Вариант 3 (гибрид) — единый источник (журнал в vault), два канала доставки.
- Приняли последовательность: сначала Вариант 1 на неделю, потом поверх добавлять YouGile-канал, если журнал приживётся.

**Остановились на:** реализовали MVP Варианта 1 — создали `CLAUDE.md` с протоколом сессий и папку `Директорский журнал/` с сегодняшней первой записью.

**Далее:** протестировать неделю. Если ритуал работает (Claude корректно резюмирует по утрам, Ибрагим реально использует сводку) — подключать Алана к задаче YouGile-канала. Если нет — разобраться почему до масштабирования.

## Попутно: как прикреплять файлы в Claude Code на iPad
